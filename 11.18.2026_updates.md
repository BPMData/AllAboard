## Step 1: Toggle to Hide Student Cursors / Cursor Names on a Busy Board

### Behavior & Scope

Two complementary behaviors make this work for both whole-class focus and personal preference:

- **Teacher room toggle (`hideStudentCursors`)**: When enabled by the teacher, student cursors (and their name labels) are hidden for everyone on the active board while the teacher's own cursor remains visible.
- **Local "Names" / "Cursors" quick toggle** (optional per-user UI button in the top/canvas controls, persisted in `localStorage`): lets any viewer hide cursor name labels (`cursor-names-only`) even when cursors are shown.

### Data Model & Protocol

- **`src/types.ts`**:
  - Add `hideStudentCursors?: boolean;` to `RoomSettings`.
- **`server.ts`**:
  - Add `hideStudentCursors: boolean;` (default `false`) to `RoomState` and `SerializedRoom` (backwards-compatible: `Boolean(parsed.hideStudentCursors)` on load/restore).
  - Include `hideStudentCursors: room.hideStudentCursors` in `getRoomSettingsPayload(room)`.
  - Add socket handler `teacher:set-hide-cursors` (`(hide: boolean) => ...`), guarded by `callerRecord?.isTeacher`, mutating `room.hideStudentCursors = Boolean(hide)`, calling `scheduleSaveToDisk(room, true)` and `broadcastRoomSettings(room)` (mirroring `teacher:set-lock`).
- **Optimization (`server.ts`, `cursor-move`)**:
  - Note that `cursor-move` currently trusts `cursorData` and rebroadcasts to `boardAudience(meta.roomId, boardId)`. Keep broadcasting or optionally tag `isTeacher: Boolean(senderRecord?.isTeacher)` on the server so clients never have to guess who is a teacher, or look up `users` on the client. Checking `users.find(u => u.userId === rc.userId)?.isTeacher` on the client also works if `users` is up-to-date, though tagging `isTeacher` on `cursor-move` server-side is spoof-proof.

### Client UI (`src/App.tsx`, `src/components/Canvas.tsx`)

- **`src/App.tsx`**:
  - Include `hideStudentCursors: false` in default `roomSettings` state and add `handleTeacherToggleHideCursors(hide: boolean)` emitting `teacher:set-hide-cursors`. Pass `hideStudentCursors={Boolean(roomSettings.hideStudentCursors)}` and `onTeacherToggleHideCursors` into `Canvas`.
- **`src/components/Canvas.tsx`**:
  - Add a teacher toolbar button next to Lock Board (e.g., `Cursors Off` / `Show Cursors` with `MousePointer` / `EyeOff`).
  - In the top overlay `<Layer>` (`Canvas.tsx` ~line 5266) where `Object.values(remoteCursors)` renders:
    - Skip rendering `rc` if `hideStudentCursors` is true **and** the cursor does not belong to a teacher.
    - If a local `hideCursorNames` toggle is enabled (or `hideStudentCursors` is `'names'` mode), omit the `<KonvaText>` label while keeping the `<Circle>` dot.

### Verification

- `tests/server.test.ts`: teacher sets `teacher:set-hide-cursors`, `room-settings` broadcasts it, non-teacher call is ignored, persists across `RoomStore` reload.
- `e2e/classroom.spec.ts`: student moves mouse on main board -> visible to peer; teacher toggles hide cursors -> student cursor disappears while teacher cursor stays visible.

## Step 2: Ephemeral Teacher Laser Pointer

### Behavior & Scope

- **Teacher-only tool** (`'laser'` in `ToolType`) that **never** creates `CanvasElement` objects, never touches `undo` / `elements` / `RoomStore`, and fades away automatically after ~1.2–1.5 s.
- Works on whichever board the teacher is viewing (`activeBoardId`) and automatically follows existing `boardAudience(meta.roomId, boardId)` scoping.

### Data Model & Protocol

- **`src/types.ts`**:
  - Add `'laser'` to `ToolType` (keep `CanvasElement['tool']` excluding `'laser'` just like `'pan' | 'select' | 'move-bg'`).
  - Add optional laser fields to `RemoteCursor` (or a dedicated lightweight `LaserPoint` event):
    - Option A (cleanest, zero new socket event): extend `RemoteCursor` with `laserActive?: boolean; laserPoints?: number[];` OR
    - Option B (recommended for clean separation from 50 ms cursor throttling): add socket event `laser-pulse` `{ boardId: string; x: number; y: number; active: boolean; color?: string }` emitted on pointer drag when `tool === 'laser'`.
- **`server.ts`**:
  - Add `socket.on('laser-pulse', (payload) => ...)`:
    - Verify `senderRecord?.isTeacher` (students cannot emit teacher laser pulses).
    - Validate finite `x`, `y` and `boardId`.
    - Rebroadcast via `socket.to(boardAudience(meta.roomId, boardId)).emit('laser-pulse', { userId: meta.userId, boardId, x, y, active, t: Date.now() })`.
    - Do **not** call `noteChange` or `scheduleSaveToDisk`.

### Client Rendering (`src/App.tsx`, `src/components/Canvas.tsx`)

- **`src/App.tsx`**:
  - Maintain a ref or state for incoming `laserTrail` (`Array<{ x: number; y: number; ts: number }>`, scoped to `boardId`).
  - Clear the trail on `boardId` change or `pointerup` fade-out.
- **`src/components/Canvas.tsx`**:
  - Show a `Laser` tool button in the tool palette **only when `isTeacher` is true** (`Sparkles` or `Crosshair` / red dot icon).
  - When `tool === 'laser'` and pointer is down + moving:
    - Append `{ x, y, ts: performance.now() }` to local laser buffer and throttle outgoing `laser-pulse` emissions (e.g. every ~30–40 ms or `POINT_FLUSH_MS`).
  - Render the trail in the top non-listening `<Layer>` (same layer as `remoteCursors`):
    - Use a `requestAnimationFrame` loop (active **only** while trail points exist, stopping automatically once empty so idle CPU is 0%) to fade segment opacity from `1 → 0` over ~1200 ms, plus a glowing head dot (`Circle` with soft outer halo `opacity: 0.35`).
    - Scale stroke/radius inversely with `stageScale` (`lineWidth / stageScale`) so the laser stays crisp at any zoom.

### Verification

- `tests/server.test.ts`: teacher `laser-pulse` reaches clients on the same board, is ignored on other boards, and is rejected if emitted by a student.
- `e2e/classroom.spec.ts`: teacher selects Laser, drags across canvas -> no new item in stroke count (`0 drawn`), and laser trail renders on student's canvas then fades.

### Updated Step 3: Student Status Badges (`Need Help` / `Got It` / `Done` / Clear)

- **Types (`src/types.ts`)**:

  ```ts
  export type StudentStatus = 'none' | 'need-help' | 'got-it' | 'done';
  ```

  Add `status?: StudentStatus;` and `statusUpdatedAt?: number;` to `User`.

- **Color & Label Mapping (shared helper, e.g. `src/lib/studentStatus.ts` or in `src/types.ts`)**:
  Keep one uniform mapping reused across the student status bar, `Chat.tsx` roster, and `LiveGridOverview`:

  - `'need-help'` → **Need Help** — **Amber / Yellow** (`bg-amber-100 text-amber-800 border-amber-300`, dot/icon `amber-500`, e.g. `Hand` or `HelpCircle`)
  - `'got-it'` → **Got It** — **Green / Emerald** (`bg-emerald-100 text-emerald-800 border-emerald-300`, dot/icon `emerald-500`, e.g. `ThumbsUp` or `Check`)
  - `'done'` → **Done** — **Purple** (`bg-purple-100 text-purple-800 border-purple-300`, dot/icon `purple-500`, e.g. `CheckCircle2` or `Flag`)
  - `'none'` → cleared (no badge)

- **Server (`server.ts`)**:

  - Add `status?: StudentStatus; statusUpdatedAt?: number;` to `ServerUserRecord` and include `status: record.status || 'none'` + `statusUpdatedAt` in `getRosterPayload(room)`.
  - `user:set-status` (`{ status }`): validate against `['none', 'need-help', 'got-it', 'done']`, update the caller's `ServerUserRecord`, and call `broadcastRoster(room)`.
  - `teacher:clear-status` (`{ targetUserId?: string }`): verify `callerRecord?.isTeacher`, reset `targetUserId` (or all users if omitted) to `'none'`, and call `broadcastRoster(room)`.

- **Client UI**:

  - **Student toggle bar** (visible when `!isTeacher`): three compact pill buttons — **Need Help** (yellow/amber), **Got It** (green), **Done** (purple) — clicking the active one toggles back to `'none'`.
  - **`Chat.tsx` (`Class` roster tab)**: show summary counts at the top (e.g., `2 need help · 6 got it · 4 done`), render the matching colored pill on each student row, and give teachers a `×` clear button per student plus `Clear all statuses` in the roster header.
  - **`CanvasModals.tsx` (`LiveGridOverview`)**: show the student's status badge (yellow/green/purple) on each sub-board card header (with a stop-propagation clear button for the teacher), plus an optional **"Need Help first"** sort priority (`need-help` → `got-it` → `none` → `done` or `need-help` first, then `done`, etc.).

- **Tests**:
  - `tests/server.test.ts`: validate all four values (`none`, `need-help`, `got-it`, `done`), reject invalid strings, verify `roster-sync` updates, and verify teacher single/all clear permissions.
  - `e2e/classroom.spec.ts`: student cycles `Need Help` → `Got It` → `Done`, teacher sees the updated badges in the roster / grid overview and clears them.

## Step 4: Spotlight / Share an Anonymized Breakout Board to Main

### Behavior & Scope

From **`LiveGridOverview`** (or while inspecting a sub-board in `Canvas.tsx`), the teacher clicks **"Spotlight to Main"** on any sub-board (`r1_ind_...` or `r1_grp_...`):

- Opens a small confirmation popover/modal with two options:
  1. **Anonymize student names** (checked by default): strips author attribution (`userId` -> teacher's `userId` or `'spotlight'`, `userName` -> `'Class Example'`) and **strips `'username'` stamps** (or replaces their `text`/label with `'Student'` so a student's name stamp doesn't leak identity).
  2. **Move everyone back to Main** (checked by default if currently in a breakout mode) and **replace vs. clear main board ink first** (default: replace main board elements with the spotlighted board's elements, and optionally copy its worksheet background if different or keep Main's background).

### Data Model & Server Handler (`server.ts`)

- Add `teacher:spotlight-board` (`payload: { sourceBoardId: string; anonymize?: boolean; copyBackground?: boolean; returnToMain?: boolean }`, `callback`):
  1. Verify `callerRecord?.isTeacher`.
  2. Look up `sb = room.subBoards.get(payload.sourceBoardId)`. Return `{ ok: false, error: 'Board not found.' }` if missing.
  3. Clone `sb.elements` with fresh IDs (`crypto.randomUUID()` or `spot_<id>` so future edits/deletes never collide with the sub-board's element IDs) and rewrite `boardId: 'main'`.
  4. **If `anonymize` (default `true`)**:
     - Overwrite `userId` with `meta.userId` (teacher) so students can't erase/drag the spotlighted work as "theirs" while it's on Main, and set `userName` to `'Class Example'`.
     - For elements where `el.stamp === 'username'`: either omit them or replace `userName` with `'Student'` (note how `Canvas.tsx` renders `username` stamps using `el.userName` / `el.text`—check `renderElement` in `Canvas.tsx` so both are anonymized!).
  5. **Background handling (`copyBackground`)**:
     - If `copyBackground` is true, clone `sb.background` via `cloneBackground(sb.background)` and run `internBackground(store, ...)` (so `/api/assets/<hash>` stays valid and GC-tracked), assign `room.background`, and broadcast `io.to(room.id).emit('background-sync', { boardId: 'main', background: room.background })`.
  6. Replace `room.elements = clonedElements`:
     - Call `noteChange(room, 'main', { full: true })`.
     - Broadcast `io.to(boardAudience(room.id, 'main')).emit('state-sync', { boardId: 'main', elements: room.elements })`.
     - Also handle **`returnToMain`**: if `payload.returnToMain` is true and `room.breakoutConfig.mode !== 'main'`, call the same `return-to-main` logic (`room.breakoutConfig.mode = 'main'; room.breakoutConfig.autoIndividual = false; broadcastBreakoutSync(room)` and update `placeSocket` for sockets moving back to `'main'`).
     - Wait: notice `placeSocket` in `server.ts`! When a socket moves from a breakout board back to `'main'`, `placeSocket` sends `state-sync` for `'main'`. Make sure `room.elements` is updated **before** moving sockets back to `'main'` so late/returning sockets get the spotlighted board automatically in one pass.
  7. Call `scheduleSaveToDisk(room, true)` and ack `{ ok: true }`.

### Client UI (`src/components/CanvasModals.tsx`, `src/components/Canvas.tsx`, `src/App.tsx`)

- **`src/App.tsx`**:
  - Add `handleTeacherSpotlightBoard(payload)` wrapping `socket.emit('teacher:spotlight-board', payload, ack)`.
- **`src/components/CanvasModals.tsx` (`LiveGridOverview`)**:
  - Add a **"Share to Main"** button (`Share2` or `MonitorUp` icon) on each sub-board card footer (stop propagation so clicking it doesn't just open the sub-board).
  - Clicking opens a lightweight inline confirmation modal (`Anonymize names [x]`, `Copy worksheet [x]`, `Bring class to Main [x]`) -> on confirm, calls `onSpotlightBoard(...)`, selects `'main'`, and closes `LiveGridOverview`.
- **`src/components/Canvas.tsx` (`renderElement` check)**:
  - Double-check how `stamp === 'username'` reads its label in `Canvas.tsx` so anonymized elements display `'Student'` rather than falling back to anything else.

### Verification

- `tests/server.test.ts`:
  - `teacher:spotlight-board` with `anonymize: true` clones elements onto `main` with fresh IDs, `boardId: 'main'`, rewritten `userId`/`userName`, leaves the original sub-board untouched, copies `background` when requested, and moves students back to `main` receiving the spotlighted elements.
  - Non-teacher calls are rejected.
- `e2e/classroom.spec.ts`:
  - Student draws + places a `username` stamp on an individual breakout board -> teacher clicks **Share to Main** (anonymized) -> everyone returns to Main and sees the drawing without the student's name.
